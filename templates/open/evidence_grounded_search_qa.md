# evidence_grounded_search_qa：基于可见证据的搜索问答

## 一句话定义

围绕冻结历史中的真实信息提出一个需要检索和综合的问题，只凭 `user behaviors` 回答，并在证据不足
时明确拒答或限定结论。

## 出题条件

题型是“可答性判断 + 证据内回答/限定拒答”。Target 包括 `answerability`、结论、最小证据和不可确定部分。gold 是 user behaviors 内经审查的可答性与证据集；答案可以是“证据不足”，不必强行产生实体结论。

只有同时满足以下条件时才出题：

1. user behaviors 中存在一个可明确表述的查询目标；
2. 回答需要综合至少两条事件、两个来源或同一对象的多个属性，而不是直接复制一行；
3. 能在 user behaviors 中确定“可回答”或“证据不足”的边界；
4. query 不要求外部知识、平台实时状态或输入中未提供的事实。

如果只能提出常识题、主观推荐题或一个无法判断证据充分性的宽泛问题，则不出题。

## 题目怎么问

Composer 应生成一个自然、具体、有业务意义的 query，并把它写进 `question`。题面必须明确：

- 只能使用当前用户历史；
- 是否先判断可答性；
- 答案需要包含哪些结论、证据与限制；
- 证据不足时怎样作答；
- 引用证据的方式和篇幅要求。

为了训练不同指令，题目可以要求“先给结论再列证据”“先判断可答性，再回答或拒答”，也可以要求
简短说明如何定位证据后再回答。该说明只能涉及已给出的 user behaviors，不得调用外部工具或生成虚假搜索结果。

## 可用信息

- `user behaviors` 是唯一检索语料和事实源；`future user behaviors`、外部搜索结果和模型常识均不得补事实。
- Composer 可以围绕 user behaviors 生成自然查询，但不得把 future user behaviors 改写成 query。
- 回答要区分原文事实、基于多条事实的克制归纳和无法确定的信息。
- 用户历史中没有出现不等于确定不存在；缺证据时回答“不足以判断”，不能给否定事实。
- 保留专有名词、时间、数字和动作原义；不得把他人笔记内容改写成用户本人经历。

## 回答与评分

- 自然语言：结论、证据、限制三段；
- 分点：`answerability`、`answer`、`evidence`、`uncertainty`；
- JSON：字段由题面完整说明；
- 表格：结论要点、证据引用、证据强度。

协议必须允许证据不足时输出明确的拒答结果，不能强迫模型为所有 query 编造答案。

本任务只保存最小的 user behaviors 可见证据，不保存 future user behaviors。Scorer 按以下维度给 0 到 1 分：

1. **可答性判断**：正确判断 user behaviors 是否足以支持结论；不把缺失当否定事实。
2. **答案正确性**：结论与 user behaviors 一致，关键实体、时间、数字和动作准确。
3. **证据覆盖**：引用支持核心结论的最小充分证据，跨来源综合关系合理。
4. **Grounding**：没有外部知识、隐藏未来、虚构检索结果或行为含义升级。
5. **冲突与不确定性**：冲突证据被保留；证据弱时使用匹配强度的表述或拒答。
6. **协议遵循**：满足题面明示的结构、证据引用、篇幅和拒答格式。

可答题与不可答题都可以得到满分；评分关注是否根据证据作出正确处理，而不是要求一定给出实体答案。
可答性、答案事实、关键实体/时间/数字、证据覆盖和限制条件全部准确得 1；结论基本正确但漏少量次要证据、限制或不确定性得 0.5；应拒答却强答、事实错误、证据不支持结论或核心信息大量遗漏得 0。答案准确性、证据充分性和信息完整性为主维度，措辞与组织方式不单独扣分。使用外部知识、虚构检索结果、未披露的未来信息或把缺失当否定事实属于硬失败。

## 可选变化

- **可答性边界**：设计“可回答/部分可回答/证据不足”的近邻例，例如 user behaviors 能确认比较行为，但不能确认最终选择或使用效果。
- **跨来源综合**：答案需同时使用搜索、Note 交互和商品行为中的最小证据，并保留各来源的动作含义。
- **冲突证据**：不同时间或来源给出不一致信号时，要求限定结论、并列冲突，而不是选一条强行回答。
- **精确约束回查**：query 同时询问实体、时间、数字或动作时，每个子结论分别评估是否有证据，允许部分拒答。

不得通过外部搜索、冷僻常识、泄漏 future user behaviors 答案或强迫不可答 query 给出猜测来提高难度。

user behaviors 中有多个时间点的搜索、笔记点击和商品浏览。题目问“现有记录能否确认用户近期比较过哪两类
商品？请列证据并说明不能确认的部分”。回答综合多条事件，同时明确仅浏览不能证明购买。

## 种子提示词

围绕题面中的用户历史回答具体问题，并先判断现有证据是否足以支持全部或部分结论。可答时给出准确结论、最小充分证据和必要限制；部分可答时分别说明可确认与不能确认之处；不可答时明确拒答，不把缺失当否定事实。不得调用外部工具、使用外部知识、补未来事实或升级行为含义。
## 不出题/不合格

- 问“哪款产品效果最好”，但 user behaviors 没有测评结论且需要外部知识。
- 把 future user behaviors 中出现的成交商品写进 query，造成答案泄漏。
- user behaviors 没有城市信息，却回答具体城市服务。
- 证据不足时仍输出一个看似完整的推荐答案。
