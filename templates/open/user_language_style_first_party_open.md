# user_language_style_first_party_open：第一方语言风格抽取

## 一句话定义

只从冻结 `user behaviors` 中由用户本人主动撰写的文本，抽取可复用的表达风格特征并绑定原文证据。

## 出题条件

1. user behaviors 中至少有两段可确认由用户本人撰写的非模板文本，且总量足以判断至少一项形式特征；
2. 文本有可定位的事件编号或原文片段；
3. 每个风格特征至少由两处证据支持，或明确标为“单样本，不足以判定稳定风格”。

只有他人内容、query、单个极短回复或无法确认作者归属时，Composer 必须返回空结果。

## 题目怎么问

Composer 要求抽取最多 N 个风格特征，每项包含特征名、形式描述、两个最短证据引用、置信度和适用边界。题面明示样本不足时的空结果。隐藏评分配置保存允许特征、第一方证据与禁止推断。

## 可用信息

- user behaviors 使用冻结的原始行为；future user behaviors 不参与答案或评分。
- 只使用用户本人的发布、评论、回复或其他明确第一方撰写文本；不使用他人 Note 正文、ASR/OCR、搜索词或平台标签。
- 可描述句长、语气、结构、称呼、表情/标点和信息密度；不从这些特征推断人格、教育、职业、年龄、性别或其他身份。
- 原文引用保持最短充分，不复述原始 ID 或整段用户文本。

## 回答与评分

- 有界自然语言；
- 按重要性排序的编号要点；
- 键值或表格；
- 固定字段 JSON；
- 证据卡片。

回答形式必须服务语义目标；不能只把同一答案机械地换成另一种外壳。

1. **第一方归属**：所有证据都来自用户本人撰写文本。
2. **特征正确性**：句式、语气、结构、标点等描述与原文一致。
3. **证据充分性**：稳定特征有多样本支持，单样本不被过度概括。
4. **形式/内容边界**：不把内容主题、兴趣、人格或身份当成语言风格。
5. **选择性与不确定性**：不用微弱特征凑数，样本少或风格不一致时明确保留。
6. **协议遵循**：字段、条数、引用长度、置信度和空结果符合题面。

第一方文本归属、语言特征、跨样本稳定性、证据引用和主要特征覆盖全部正确得 1；特征基本成立但样本覆盖不足、置信度偏高或漏少量次要特征得 0.5；混入他人文本、把主题/人格当语言风格、引用不支持结论或遗漏主要稳定特征得 0。特征准确性、证据充分性和信息完整性为主维度，格式只占较低权重。使用未披露的未来信息、编造原话、敏感身份推断或单样本过度概括属于硬失败。

## 可选变化

难度只能通过同类型近邻干扰、多来源证据、时间变化、多个可独立评分 target 或严格的压缩/格式约束提高；
不得靠无关选项、超长输入、冷僻外部知识或泄漏后再绕写题面制造表面难度。

根据同一份冻结的 user behaviors 中的多源证据完成有界归纳；答案明确区分可见事实、谨慎推断和未知项，并严格遵守题目协议。

## 种子提示词

只能使用用户消息中“用户记忆”部分给出的本观察窗口可见文本，不得把窗口之外的过去或未来表达补进结论，不得调用工具、补充外部知识、推断兴趣、人格或人口与敏感属性，也不得读取或复述任何原始 ID。每条有效结论都必须引用消息中真实出现的 EV 编号。只输出一个严格 JSON 对象，不要 Markdown、解释、评分、reward、winner 或 teacher-win。

作答时先基于输入中的可见证据分析相关行为与待输出结论之间的联系，再按上述任务格式给出结果。证据不足时可以明确说明，不得为了形成结论而补写输入之外的信息。
## 不出题/不合格

- 根据单次曝光推断稳定兴趣；
- 把他人 Note 内容写成用户本人经历；
- 使用输入外品牌、城市、机构或身份；
- rubric 只写“答案合理”而没有可检查维度；
- user behaviors 没有供给仍强行出题。
