# content_entity_attribute_extraction：内容实体与属性抽取

## 一句话定义

从冻结的 `user behaviors` 中抽取明确出现的实体、属性和对应证据，不补全输入中没有的信息。

## 出题条件

题型是只使用 user behaviors 的开放抽取。Target 是题面指定的实体、属性、关系和对应证据。gold 由 user behaviors 中可直接定位的字段与原文组成；不使用 future user behaviors 生成 gold，也不把用户兴趣、意图或画像当作实体属性。

只有同时满足以下条件时才出题：

1. `user behaviors` 中至少存在两个可区分的实体，或一个实体至少带两个明确属性；
2. 目标实体和属性能由原文直接定位，而不是依靠外部知识推断；
3. 题目要求的不只是抄写一个字段，而是需要跨事件归并、同名去重、属性对齐或冲突保留中的至少一项。

只有 ID、时间或无语义占位值时不出题。实体或属性供给不足时，Composer 返回空结果，不硬凑字段。

## 题目怎么问

Composer 根据当前 user behaviors 选择少量有信息量的实体类型和属性，生成完整的 `system_prompt` 与
`question`。题面必须明确：

- 要抽取哪些实体类型或允许模型自行识别哪些类型；
- 每个实体需要哪些属性；
- 如何引用证据；输入没有证据编号时，允许引用日期、事件序号或最短原文片段；
- 缺失属性如何表达；
- 重复和冲突如何处理；
- 条目上限或篇幅限制。

题目不得要求 Student/Teacher 猜测隐藏 schema，也不得把隐藏评分配置中的参考答案泄漏到题面。

## 可用信息

- 事实源只有逐字冻结的 `user behaviors`；`future user behaviors` 和 distractor pool 均不得用于生成答案或评分。
- 实体名称、属性值、动作、时间和关系必须在 user behaviors 中明确出现。
- 不用常识补品牌归属、商品功能、人物身份、地点层级或内容类别。
- 搜索、曝光、点击、浏览、收藏、评论、分享、关注、加入购物车和成交保持原动作含义。
- 同一实体跨事件重复出现时可以合并证据，但不同时间、不同值或无法确认同一性的记录不得强行合并。
- 冲突属性并列保留并标为冲突或不确定，不擅自选择一个“正确值”。

## 回答与评分

协议随具体题目选择，不固定为 JSON。可采用：

- JSON 实体数组：每项包含 `entity`、`entity_type`、`attributes`、`evidence_refs`；
- Markdown 表格：实体、类型、属性、证据、冲突或不确定性；
- 分点清单：每个实体一项，属性与证据写在同一项内。

无论采用哪种形式，题面和 `response_protocol` 都必须明示必需字段、允许的缺失表达与等价形式。

本任务只保存最小的 user behaviors 可见证据，不保存 future user behaviors。Scorer 按以下维度给 0 到 1 分：

1. **实体正确性**：抽取的实体确实出现，重要实体无明显漏抽；不因外部知识增加实体。
2. **属性正确性**：属性和值与实体正确对齐，缺失时保持缺失，不编造默认值。
3. **证据对应**：每项能指向真实可见证据，引用足以定位原文。
4. **去重与冲突**：同一事实合理去重；跨时间差异或冲突被保留，不被错误覆盖。
5. **动作与身份边界**：不升级行为含义，不由弱行为推断敏感身份或生活经历。
6. **协议遵循**：满足题面明示的结构、字段、数量和篇幅要求。

内容正确性是主要得分。只要语义和证据对应正确，允许使用协议明示的等价表达。
实体、属性、证据和核心覆盖全部正确得 1；实体正确但漏少量非核心属性、证据范围偏宽或冲突说明不完整得 0.5；实体不存在、属性挂错实体、证据无法定位或核心实体大量遗漏得 0。实体/属性准确性和信息完整性为主维度，格式只占较低权重。使用外部知识补默认属性、推断敏感身份或引用未披露的未来信息属于硬失败。

## 可选变化

- **跨事件归并**：同一实体在搜索、Note 交互和商品行为中反复出现，要求合并实体但保留每个属性的证据来源。
- **近邻实体消歧**：提供同品牌不同型号、同名不同对象或名称略有差异的记录，只在 user behaviors 中的证据能确认同一性时合并。
- **属性冲突**：让同一实体在不同时间或来源出现不同值，要求并列值、时间和证据，不做无依据裁决。
- **局部缺失**：部分实体缺少某属性时，要求保留实体并按协议写“未知”，不用其他实体或常识补值。

不得通过要求外部知识、隐藏实体原文、增加无语义 ID 或把兴趣/意图伪装成属性提高难度。

user behaviors 中多次出现同一品牌的两款商品、各自品类和不同动作。题目要求抽取商品、品牌、品类和可见
动作，并合并同一商品的重复记录。答案只写输入出现的值，并为每个属性引用事件序号。

## 种子提示词

只从题面给出的正文、OCR、ASR、视觉描述或行为文本中抽取指定类型的实体、属性和值，并为每项保留可定位的最小证据。相同实体只在可确认同一时合并，重复事实去重，冲突值并列并注明来源或时间，缺失属性明确写未知。不得使用外部知识补默认值，不得把兴趣、意图或模型描述升级成确定属性，也不得由弱行为推断敏感身份。
## 不出题/不合格

- user behaviors 只出现一个商品名，题目却要求推断价格、成分和适合人群。
- 把“点击某品牌笔记”抽取成“用户喜欢该品牌”。
- 因两个相似名称就把不同商品合成一个实体。
- 隐藏评分要求严格 JSON，但题面只要求“列出实体”。
- 只有 ID 或占位值时仍强行出题。
