# interest_profile_behavior_open：行为证据内容兴趣抽取

## 一句话定义

只根据冻结的 `user behaviors`，抽取本观察窗口内的内容兴趣主题，并为每个主题绑定可定位行为证据。

## 出题条件

1. user behaviors 中至少有一个由主动搜索、有效观看、收藏、评论、分享、关注或重复点击支持的内容主题；
2. 每个主题至少有一条局部行为编号或其他可定位证据；
3. 能区分重复主题与一次性触达。

若只有曝光、无点击触达或无语义事件，Composer 必须返回空结果。

## 题目怎么问

Composer 要求抽取最多 N 个兴趣，每项包含主题、最小证据引用、证据摘要、置信度和不确定性。题面明示近义主题合并规则与空结果写法。隐藏评分配置保存规范化主题、可接受合并关系和 user behaviors 中的最小证据。

## 可用信息

- user behaviors 必须逐字保留冻结的原始行为，不得由 Composer 改写；
- future user behaviors 不进入答案，也不保存为本模板的 future user behaviors；
- 只能使用 user behaviors 中明确出现的事实、实体、时间和动作；
- 平台标签必须注明来源性质，不能当作用户自述；
- 搜索、浏览、曝光和单次互动不能自动升级为长期偏好、身份或经历。

## 回答与评分

- 历史严格 JSON `interests[]`：适合字段与证据编号遵循。
- 兴趣—证据对照表：适合评估主题合并和置信度。
- 紧凑证据卡：每张卡片只表达一个内容兴趣。

协议不得增加广告建议、人口画像或未来意图字段。

1. **主题正确性**：兴趣主题与可见内容/行为一致。
2. **证据对应**：每个主题引用真实局部编号，摘要能支持结论。
3. **强度与置信度**：不把曝光或单次弱动作当稳定兴趣。
4. **合并与去重**：近义主题合理合并，不丢失可区分主题。
5. **语义边界**：不产出广告建议、人口/敏感画像或用户未明示经历。
6. **协议遵循**：字段、条数、置信度枚举、证据引用和空结果符合题面。

主题、强度、时间性、证据和主要兴趣覆盖全部正确得 1；主题大体正确但置信度偏高、证据单薄或漏少量次要兴趣得 0.5；主题无依据、把曝光当稳定兴趣、证据错配或遗漏主要兴趣得 0。主题准确性、证据对应和信息完整性为主维度，格式只占较低权重。输出广告建议、人口/敏感画像、未披露的未来信息或用户未明示经历属于硬失败。

## 可选变化

难度只能通过同类型近邻干扰、多来源证据、时间变化、多个可独立评分 target 或严格的压缩/格式约束提高；
不得靠无关选项、超长输入、冷僻外部知识或泄漏后再绕写题面制造表面难度。

根据同一份冻结的 user behaviors 中的多源证据完成有界归纳；答案明确区分可见事实、谨慎推断和未知项，并严格遵守题目协议。

## 种子提示词

只能使用用户消息中给出的本观察窗口可见事实，不得把窗口之外的过去或未来行为补进结论，不得调用工具、补充外部知识、猜测人口属性或敏感属性，也不得读取或复述任何原始 ID。每条结论都必须引用消息中真实出现的局部行为编号。只输出一个严格 JSON 对象，不要 Markdown、解释、评分、reward、winner 或 teacher-win。

只总结本观察窗口：根据用户消息中的完整行为片段，综合其中可见的来源、动作、时间和内容，概括该段行为体现的内容兴趣。不得引用或猜测本窗口结束后的行为。不要把单次曝光当兴趣，不要把弱动作升级为强意图，也不要推断年龄、性别、地域、职业、收入、教育、健康、政治、宗教、民族或性取向。无法确定时降低 confidence 并明确 uncertainty；不要为了填满字段而猜测。

输出 schema 必须严格为：
{
  "interests": [
    {
      "topic": "简短主题",
      "evidence_refs": ["[E000001]"],
      "evidence_summary": "对引用证据的简洁概括，禁止长段复制",
      "confidence": "high|medium|low",
      "uncertainty": "证据边界或不确定性"
    }
  ],
  "overall_uncertainty": "整体证据覆盖范围与局限"
}
对象和子对象都不得增加字段。evidence_refs 只能引用下方用户行为中可见的局部编号；最多输出 12 个兴趣。

作答时先基于输入中的可见证据分析相关行为与待输出结论之间的联系，再按上述任务格式给出结果。证据不足时可以明确说明，不得为了形成结论而补写输入之外的信息。
## 不出题/不合格

- 根据单次曝光推断稳定兴趣；
- 把他人 Note 内容写成用户本人经历；
- 使用输入外品牌、城市、机构或身份；
- rubric 只写“答案合理”而没有可检查维度；
- user behaviors 没有供给仍强行出题。
