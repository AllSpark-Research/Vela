# author_follow_author_attribution：完整单题模板

## 一句话定义

解释预测窗口内真实发生的内容促成关注，与此前可见的作者接触和兴趣轨迹之间的证据联系。

## 出题条件

本 leaf 的业务口径不可由 Composer 临时改写：

| 项目 | 固定值 |
|---|---|
| source task | `author_follow` |
| source question | `choice_author_multi` |
| gold source | `author_follow` |
| target | `author` |
| 题面中的已发生结果名 | 未来关注作者 |
| source answer 形态 | 多标签集合；窗口内全部合格 label 去重后公开为结果事实 |

源 objective 只接受内容渠道（发现 feed 或搜索页）、存在来源标识、非互关且作者画像可用的真实关注；gold 是这些关注作者的去重卡片标签。

归因任务只从已物化的来源客观题的隐藏 gold 文件取结果。文件中的 `card`、`gold_source`、候选编号、`choice` 与 `is_gold` 必须彼此一致；抽取器只按 gold 编号取 label，并按稳定首次出现顺序去重。候选全集、非 gold 候选和 `is_gold` 永不进入 Student 可见字段。

只有同时满足以下条件才可实例化本 leaf：

1. `user behaviors` 已在观察时点冻结，且观察事件与预测事件索引不相交；
2. 存在精确匹配 `author_follow/choice_author_multi` 的 来源客观题，且至少有一个合格 gold label；
3. source gold 使用 `author_follow` 与 `author` 的固定口径，不能从相邻 target 或另一个 source 借值；
4. 预测窗口事件索引非空、结果 label 不含不可展示标识，追加结果后仍在冻结 context budget 内；
5. Composer 能从 source gold 生成一个或多个 `[F……]` 结果事实，同时保留原 `[E……]` 观察证据编号；
6. source artifact 缺失、字段不一致、gold 为空、窗口不完整、label 不安全或会泄漏候选答案时，返回空结果，不编造补齐。

## 题目怎么问

核对同一作者或同领域作者的重复触达、长看/收藏/评论等深互动、主动搜索或第一方表达；同作者证据强于仅同领域证据。

动作与语义边界：关注仅表示发生了关注动作，不等于认同作者全部观点，也不能把他人笔记内容写成用户本人经历。

本题解释“哪些可见事实与已发生结果可能有关”，不证明因果。时间先后、主题相似或同一实体都不能单独证明结果由某条行为导致。

当前 leaf 只解释真实发生的关注。若可见历史无法解释该关注，应输出无联系 fallback；不得另问“为什么没有关注某作者”，因为本 leaf 没有绑定完整机会集与未关注 gold。

同一作者从未在历史出现、只有一次弱曝光、历史集中在别的领域，或关注与最后相关证据间隔很长时，应作为反证或缺口。

若没有可靠联系，正确答案必须令 `supporting_evidence=[]`，让 `counter_evidence_or_gaps` 第一项精确写为“当前证据无法解释该结果”，并把 `confidence` 设为 `low`。这是完整可得分负例，不是拒绝出题失败。

Composer 必须：

1. 原样保留 source gold 生成的全部 `[F……]` label，不挑一个更好解释的结果；
2. 题目明确说明结果已发生，禁止再次预测、评价候选或猜 gold；
3. 要求回答分别给出结果复述、支持证据、行为变化、反证/缺口、替代解释和置信度；
4. 在隐藏评分配置中保存 source task/question、gold source、target、source gold hash、future user behaviors 中的最小证据与下述逐项 rubric；
5. 不把本结果对应的 `author_follow` objective 子题放进同一 复合题；该 objective 会直接泄漏待解释结果；
6. 只在其他子题拥有独立 gold/rubric 且不泄漏本结果时组合，所有子题独立评分后取 macro average。

## 可用信息

Student 与 Teacher 可见逐字冻结的 `user behaviors`、其中的 `[E……]` 观察证据，以及如下形式的真实结果：

```text
已发生的未来结果（仅用于解释，不需要再次预测）：
[F000001] 预测窗口内实际发生的未来关注作者：<source gold label>。
```

答题者看不到原始 `future user behaviors`、来源客观题的候选全集、`choice`、`is_gold`、source gold hash，也看不到评分程序从 future user behaviors 保留的最小证据。评分时可以使用这些隐藏材料核对结果口径和 rubric。答案只能引用题面已有的 `[E……]` 和 `[F……]`；每条支持证据必须至少包含一个 E 编号和一个 F 编号。

## 回答与评分

默认协议是一个 JSON object，顶层字段固定为：

```json
{
  "result_summary": "只复述题面 [F] 结果",
  "supporting_evidence": [{
    "evidence_refs": ["[E000001]", "[F000001]"],
    "observation": "可见事实",
    "connection": "与该结果的可能联系"
  }],
  "behavior_evolution": ["有证据的时间变化；没有则空数组"],
  "counter_evidence_or_gaps": ["反证或信息缺口"],
  "alternative_explanations": ["不能由当前证据排除的其他可能解释"],
  "confidence": "high|medium|low"
}
```

不得输出未在题面出现的证据编号。Composer 若改成表格、编号要点或有界自然语言，必须在最终 question 中完整写明等价字段，并同步改写 Scorer 的协议 rubric；不能保留隐藏 JSON 门槛。

每项独立给 `0 / 0.5 / 1`，默认等权平均；多条 F 结果必须逐个覆盖，遗漏按对应项比例扣分。

1. **R1 结果忠实度**：准确覆盖全部 未来关注作者 F label，不增加 target、动作、次数或窗口外事实。
2. **R2 证据可核对性**：每条支持链同时引用真实 E ref 与对应 F ref，observation 可从题面逐字核对；编造证据为 0。
3. **R3 与目标直接相关的 联系**：核对同一作者或同领域作者的重复触达、长看/收藏/评论等深互动、主动搜索或第一方表达；同作者证据强于仅同领域证据。
4. **R4 动作与语义边界**：关注仅表示发生了关注动作，不等于认同作者全部观点，也不能把他人笔记内容写成用户本人经历。
5. **R5 反证与缺口**：同一作者从未在历史出现、只有一次弱曝光、历史集中在别的领域，或关注与最后相关证据间隔很长时，应作为反证或缺口。
6. **R6 替代解释与置信度**：替代解释只写可能性；证据单一、冲突或间隔长时不得给 high。正确 no-link fallback 本项可得 1。
7. **R7 协议遵循**：满足题面明示的字段、证据编号、条数与格式；格式只在明确写进 question 时扣分。

## 可选变化

用多个相近作者、同领域但不同作者的重复互动、兴趣转折和时间间隔构造近邻辨别；不能用陌生作者或缺画像候选凑难度。

合格正例要求至少一条与目标直接相关的支持链，同时保留真实反证或缺口。合格负例包括：目标结果真实发生，但 user behaviors 中没有可核对联系；模型应拒绝牵强解释。

## 种子提示词

你的任务是解释“未来关注作者”这一已经发生的未来结果与此前可见行为之间有哪些证据联系。这里的“归因”是证据归因，不是因果证明。

任务边界：
1. 用户消息先给出冻结观察段的原始行为，随后给出预测窗口内已发生的未来关注作者。结果已经发生，不需要再次预测或评价候选项。
2. 解释关注作者结果时，重点检查此前对该作者或同领域作者的重复接触、深度互动和主动表达；关注不等于认同作者全部观点。
3. 只使用输入中可见的事实和证据编号。不得补写输入外商品、品牌、地点、身份、动机、价格或经历。
4. 严格保留动作含义：曝光、浏览、点击、收藏、评论、分享、关注、搜索、加购、下单和购买不能相互升级。
5. 时间先后只能支持“可能相关”的解释，不能单独证明因果。必须保留替代解释，例如偶然触达、外部信息、价格促销或证据缺失；没有可见依据时不要把替代解释写成事实。
6. 他人内容只说明用户接触或互动过相关内容，不代表其中经历属于用户本人。平台标签不是用户自述。
7. 如果历史行为与结果联系很弱、存在反例或时间间隔过长，应降低 confidence；证据不足是合格结论。
8. 如果可见历史与已发生结果之间没有可靠联系，必须让 counter_evidence_or_gaps 的第一项明确写“当前证据无法解释该结果”，supporting_evidence 输出空数组；随后说明缺失的证据，并将 confidence 设为 low；不得为了填满字段牵强建立联系。
证据写法：
- supporting_evidence 中的 evidence_refs 必须引用输入中真实存在的观察证据 [E……] 和结果证据 [F……]。
- observation 只复述可见事实；connection 用克制语言说明它与已发生结果的可能联系。
- behavior_evolution 按时间写可见行为如何变化，不存在变化链时输出空数组。
- counter_evidence_or_gaps 记录反向信号、缺失信息、单次弱行为或时间跨度问题。
- alternative_explanations 只能写“可能的其他解释”，不能伪装成已发生事实。
- confidence 只能是 high、medium 或 low。

作答时先基于输入中的可见证据分析相关行为与待输出结论之间的联系，再按上述任务格式给出结果。证据不足时可以明确说明，不得为了形成结论而补写输入之外的信息。

只输出一个合法 JSON object，不含 Markdown、代码围栏或额外文字。字段和结构固定为：
{
  "result_summary": "简要复述已发生的未来关注作者，不得添加新事实",
  "supporting_evidence": [{
    "evidence_refs": ["[E000001]", "[F000001]"],
    "observation": "可见事实",
    "connection": "与结果的可能联系"
  }],
  "behavior_evolution": ["按时间可见的变化"],
  "counter_evidence_or_gaps": ["反向证据或信息缺口"],
  "alternative_explanations": ["不能由当前行为排除的其他可能解释"],
  "confidence": "high|medium|low"
}
## 不出题/不合格

以下均不合格：

- 再次预测已经给出的 F 结果，或输出 来源客观题的候选答案；
- 用先后关系、相似主题或一次曝光声称确定因果；
- 把曝光、浏览、点击、收藏、关注、搜索、加购、下单、成交互相升级；
- 编造用户身份、动机、价格、经历、外部事件或不可见内容；
- 忽略相反行为、竞争实体、证据粒度不足或时间断裂；
- 与解释同一结果的 来源客观题 放进同一 复合题。
