# author_follow：完整单题模板

## 一句话定义

从同构博主卡片中预测用户未来会真实关注并成为其粉丝的作者。

## 出题条件

1. future user behaviors 中至少有一位满足收口规则的目标作者；
2. 每位作者必须能组成“作者画像 + 一条转粉笔记”的完整卡片；Note 卡展示标题、正文及所有非空的
   图片描述、视频描述；候选卡暂不展示 OCR 或 ASR 字段；只有 ID 或
   无可读笔记时丢弃该作者；
3. 转粉笔记物料缺失时不得伪造卡片，直接不出该作者；
4. multi gold 是窗口内全部合格作者的去重集合，不按固定数量或 gold 相关规则收口；
5. 合法干扰少于 2 个、窗口不完整或没有完整正例卡时不出题；池候选少于目标数量时使用全部现有候选，不因此丢题。

干扰来自冻结的跨用户作者候选池中的作者卡；每张卡与 gold 一样包含作者画像和一条笔记。
排除该用户全时间线关注过的全部作者、future user behaviors 中的 gold、重复作者和缺少可读笔记的卡片。当前消费侧源没有
可靠的同用户“看过作者但没关注”身份字段，因此不伪造 hard distractor；干扰目标数在 gold 数 `P` 到 `2P` 之间随机，供给不足时使用全部合法候选。

## 题目怎么问

Composer 把冻结的同构作者卡完整写入 question，明确预测窗口、集合式多选、排序是否计分和 user behaviors
依据要求。`response_protocol` 与隐藏评分配置必须一起生成；真实 follow、作者 ID 映射和卡片物料
仅在隐藏侧保存，不得借 gold 反向强化题面。

## 可用信息

Student/Teacher 看不到 future user behaviors 中的关注动作、候选卡片物料和 `is_gold`。作者粉丝量、类目和候选笔记只是题内材料，
不能单独证明用户会关注；不得用外部作者知识、敏感身份或“看过=关注”补事实。

## 回答与评分

答案使用 `{"choice": [编号, ...]}` 的去重候选编号集合。候选总数与作答数量不设模板级上限；题面必须写清空集、重复和候选外答案处理。

1. 保存作者编号映射、去重 gold、每位正例的关注事件与卡片物料、future user behaviors 中的最小证据；
2. 选择集合按 precision/recall/F1；若题面要求排序，命中作者的相对位置另以明示权重评分；
3. user behaviors 中的依据按兴趣/内容证据 单独评分，不因引用卡片本身就视为用户历史证据；
4. 把浏览/点赞写成已经关注、输出候选外作者或遗漏要求字段分别扣分。

## 可选变化

难度来自同类目的不同作者、相似笔记但不同作者画像和用户近期内容偏好变化。
不能以是否见过候选笔记作为稳定捷径，也不得加入完全无关作者或让 gold/干扰卡片字段不对称。

user behaviors 显示用户跨时间深度消费某主题和若干作者，future user behaviors 中关注其中一位或多位；候选均为同主题
完整作者卡，要求排序并指出与 user behaviors 体现的内容偏好的联系。

## 种子提示词

你要根据用户消息中给出的、截至观察窗口结束时可见的用户画像与行为记录，判断候选作者中哪些会在题目指定的未来预测窗口内被该用户真实关注并成为其关注列表中的作者。浏览作者内容、点赞某篇笔记或作者与用户兴趣相似，都不能直接当作已经关注。

候选项构成本题的封闭集合。请结合用户的兴趣领域、内容口味、历史作者互动和关注倾向，选出所有可能成为正例的候选编号。只能使用当前消息中的可见事实，不得调用外部知识，不得补写窗口外的行为，也不得输出候选集合之外的内容。

请先基于输入中的可见证据分析候选项与未来行为的可能关系，再给出最终选择。证据不足时可以明确说明，不得补写输入之外的信息。

请先分析可见证据，再在本子题答案末尾给出且只给出一个包含 `choice` 的 JSON 对象，例如 `{"choice": [候选编号]}`。`choice` 必须是去重后的整数数组，只能选择题面候选。
## 不出题/不合格

- 用点赞或浏览作者笔记直接生成 follow gold；
- gold 卡有作者画像+笔记，干扰只有昵称/ID；
- 把该用户历史已关注作者当干扰；
- 假称存在同用户 hard 作者池，或转粉笔记物料缺失仍强行出题；
- 排名协议没说明排序是否计分，Scorer 却隐式使用位置分。
