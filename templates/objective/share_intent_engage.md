# share_intent_engage：完整单题模板

## 一句话定义

在未来真实浏览或互动的笔记集合中，预测用户会进一步分享或转发哪些笔记。

## 出题条件

1. future user behaviors 中至少有一条带可读标题或正文、分享计数大于 0 的笔记；
2. 同一 `note_id` 的多日行先聚合，窗口内任一分享即为正例；
3. 观察窗口前已经分享过的 note 进入排除桶，避免把“记住曾分享”当未来预测；
4. gold 是完整预测窗口内合格 future user behaviors note 的去重集合，不按固定数量或 gold 相关规则收口；
5. Note 候选去重后最多 30 张；不得依据 share gold 裁切，无法在 30 张内保留完整任务语义时不出题；
6. 没有正例、可靠干扰少于 2 个、正文不可读或窗口不完整时不出题；可靠干扰数量少于目标数量时使用全部现有候选，不因此丢题。

候选全部来自该用户 future user behaviors 的真实笔记互动集合，不用跨用户池。干扰只取没有分享、点赞、收藏或评论
的“仅点击/浏览”笔记；赞/藏/评但未分享的 note 因假负风险进入不确定桶，两不沾。gold 和干扰都使用
同样的完整 Note 卡，展示标题、正文及所有非空图片描述、视频描述，暂不展示 OCR 或 ASR 字段，排除历史已分享 note、重复 note 和空内容。

## 题目怎么问

Composer 使用冻结的 future user behaviors 中真实互动 note 卡生成分享预测 question，明确窗口、集合式多选、排序规则和
理由预算。每张卡展示标题、正文及所有非空图片描述、视频描述，暂不展示 OCR 或 ASR 字段，候选去重后最多 30 张。它必须让
`response_protocol` 与隐藏评分配置对齐；share gold、赞藏评论不确定桶及
future user behaviors 中的计数不得出现在可见候选中。

## 可用信息

题面可说明候选都会被浏览或互动，但不得暴露 future user behaviors 的分享计数、其他互动计数、分层或 `is_gold`。
未分享只限定冻结窗口，不能解释为不愿传播；不得把点赞/收藏升级为分享事实。

## 回答与评分

答案使用 `{"choice": [编号, ...]}` 的去重候选编号集合。候选 Note 最多 30 张，作答数量不设固定上限；题面必须写清空集、重复和候选外答案处理。

1. 保存 note 映射、去重 share gold、历史分享排除桶、不确定桶和 future user behaviors 中的最小证据；
2. 选择集合按 precision/recall/F1；排序只在题面明示时单列较低权重；
3. 理由按 user behaviors 的内容口味与历史分享模式评分，不能引用 future user behaviors 或候选互动计数；
4. 把点赞/收藏/评论写成分享、重复或候选外 note 分别扣分。

## 可选变化

通过同主题内容中“适合自己看”与“愿意转给别人”的差异、信息实用性/社交背书、历史分享模式和近期
话题变化调节；不得把赞藏未分享项强当负例，也不得用跨用户无关 note 或卡片字段差异凑难度。

user behaviors 中用户曾分享实用攻略但只点赞审美内容，future user behaviors 中的候选同时含两类相近笔记；gold 是真实分享的
攻略，答案需要选对并用可见传播偏好简短说明。

## 种子提示词

题目给出的候选笔记会在指定的未来预测窗口内真实被该用户浏览或互动。你要根据用户消息中截至观察窗口结束时可见的用户画像与行为记录，判断哪些候选会被用户进一步分享或转发给他人。喜欢看、长时间停留、点赞或收藏都不能直接当作分享。

候选项构成本题的封闭集合。请结合用户的内容口味、分享传播倾向、社交背书意愿和历史分享模式，选出所有可能成为正例的候选编号。只能使用当前消息中的可见事实，不得调用外部知识，不得补写窗口外的行为，也不得输出候选集合之外的内容。

请先基于输入中的可见证据分析候选项与未来行为的可能关系，再给出最终选择。证据不足时可以明确说明，不得补写输入之外的信息。

请先分析可见证据，再在本子题答案末尾给出且只给出一个包含 `choice` 的 JSON 对象，例如 `{"choice": [候选编号]}`。`choice` 必须是去重后的整数数组，只能选择题面候选。
## 不出题/不合格

- 用点赞、收藏或评论计数直接生成分享 gold；
- 把赞藏未分享 note 当确定负例，或忽略观察期已分享排除桶；
- 候选来自跨用户池而非 future user behaviors 中真实互动集；
- 题面泄漏 future user behaviors 互动计数；
- 理由文采高就抵消候选选错，或排序未在题面说明却暗中计分。
