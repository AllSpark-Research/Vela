# seed_intent_ecom：完整单题模板

## 一句话定义

在未来真实曝光的商品集合中，预测哪些商品会触发“想要”动作但不会在该窗口内购买。

## 出题条件

1. 候选全集来自该用户预测窗口内真实出现的电商商品，不接跨用户池；
2. 同一商品名的多行先聚合：有心愿单/加购/立即购且购买计数等于 0 才进入正例；
3. 窗口内或全时间线任意购买计数大于 0 的商品进入购买排除桶，与本任务 gold 不相交；
4. 商品卡统一显示商品名，可附真实店铺名与电商一级类目；正例保留完整预测窗口内的全部
   合格商品，不按固定数量或 gold 相关规则收口；
5. 没有正例、可靠非购买干扰少于 2 个、窗口不完整或商品名为空时不出题；可靠干扰数量少于目标数量时使用全部现有候选，不因此丢题。

hard distractor 优先是 future user behaviors 中真实进入商详（商详浏览计数大于 0）但没有种草动作且未购买的商品；
其后用仅点击/仅曝光且未购买的商品补足。gold 与干扰都来自同一 future user behaviors 中的曝光集合、使用同构卡片。
已购买商品、同义重复和字段缺失商品既不作正例也不作干扰。

## 题目怎么问

Composer 将冻结的 future user behaviors 中的曝光商品卡作为封闭候选，生成区分“种草未购买”与“未种草”的 question，
并明确预测窗口及动作定义。它同步生成全覆盖或正例集合协议；种草动作、购买排除桶和 gold 只进入
隐藏评分配置，不得出现在商品卡中。

## 可用信息

题面可以声明候选都会在未来被展示，但不得暴露具体 future user behaviors 中的动作、层级或 gold。心愿单、加购、立即购
表示显式“想要”，不代表购买；未种草只限定当前窗口，不能解释为永久不喜欢。

## 回答与评分

答案使用 `{"choice": [编号, ...]}` 的去重正例编号集合。题面必须写清空集、重复和候选外答案处理，隐藏评分配置保存编号归一化及漏答规则。

1. 保存商品编号映射、种草动作集合、购买排除桶、去重 gold 和 future user behaviors 中的最小证据；
2. 全覆盖协议按候选级 macro-F1，正例集合协议按 precision/recall/F1；
3. 把曝光/商详浏览当种草或把种草当成交，均按动作边界扣内容分；
4. 未覆盖题面要求的候选、重复/候选外商品和标签不合法按明示协议扣分。

## 可选变化

难度由商详未深转的强干扰比例、同品类近似商品、历史购买与当前“只想要未购买”的冲突、近期需求
变化决定；不得用跨用户商品、格式不对称或仅曝光的明显无关商品大量稀释。

user behaviors 中对某类商品反复比较但购买谨慎，future user behaviors 中真实曝光多个同类商品，其中少数加入心愿单/购物车且
未买；候选同时含进入商详但未种草的强干扰，要求逐项判断。

## 种子提示词

题目给出的候选商品会在指定的未来预测窗口内真实曝光给该用户。你要根据用户消息中截至观察窗口结束时可见的用户画像与行为记录，判断哪些候选会让用户产生明确的“想要”动作，例如加入心愿单、加购或尝试立即购买。本题预测的是种草后的显式意图，不要求最终成交；仅曝光、浏览或一般兴趣不能直接当作正例。

候选项构成本题的封闭集合。请结合用户的商品兴趣、品类与品牌偏好、近期需求以及消费意图强弱，选出所有可能成为正例的候选编号。只能使用当前消息中的可见事实，不得调用外部知识，不得补写窗口外的行为，也不得输出候选集合之外的内容。

请先基于输入中的可见证据分析候选项与未来行为的可能关系，再给出最终选择。证据不足时可以明确说明，不得补写输入之外的信息。

请先分析可见证据，再在本子题答案末尾给出且只给出一个包含 `choice` 的 JSON 对象，例如 `{"choice": [候选编号]}`。`choice` 必须是去重后的整数数组，只能选择题面候选。
## 不出题/不合格

- 把购买计数大于 0 商品仍放入 seed gold；
- 只要有商详浏览计数就算被种草；
- 候选从跨用户池抽取，违背“未来真实曝光集”封闭合同；
- 题面泄漏哪些商品进入商详、加购或购买；
- 只对正例写丰富卡片，干扰只写商品名，造成格式捷径。
