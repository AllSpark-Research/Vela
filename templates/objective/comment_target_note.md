# comment_target_note：未来评论目标 Note 预测

## 一句话定义

根据冻结历史，从有界 Note 候选中预测用户在未来窗口内会真实发表评论的 Note 集合。

## 出题条件

- user behaviors 中有用户历史互动、搜索或评论线索；future user behaviors 中至少有一条真实“写评论”事件及 `note_id`。
- gold 是预测窗口内全部有效写评论事件对应的**去重 `note_id` 集合**；评论文本、情感和上游意图标签不进入题面。
- 候选由全部 gold、同主题近邻、同作者其他 Note、历史接触但本窗口未评论的 Note 构成，不用随机无关 Note 凑数。
- 每个候选都要展示完整 Note 卡，因此候选去重后最多 30 个。候选构造必须与 gold 无关，不能为了上限按是否评论裁切。
- Note 内容按 `note_id` 从集中字典加载。每张候选卡至少包含标题和正文，并补充所有非空的图片描述、视频描述。候选卡暂不展示 OCR 或 ASR 字段，且不能只给标题。
- 合法干扰少于 2 个、future user behaviors 不完整或只有无效评论时不出题；干扰目标数在 gold 数 `P` 到 `2P` 之间随机，数量不足时使用全部现有候选。

## 题目怎么问

题面给出预测窗口和编号候选，要求选择窗口内所有真实评论目标，允许选择零个、一个或多个；gold
恰好只有一个时，正确答案只是单元素集合，任务合同仍是集合式多选。协议可为字母集合、编号集合、标签集合或 JSON 数组，
但题面必须明确多选与空选规则。隐藏评分配置保存候选映射、gold 集合和等价解析规则。

## 可用信息

使用同主题 Note、同作者不同 Note、历史高互动但未评论对象作为近邻干扰；可加入跨时间需求变化。
不使用随机无关 Note，不把未评论解释成不喜欢，不由评论预测敏感身份。

## 回答与评分

按候选集合计算 precision、recall 与 F1；不切换为单选 exact match。可选的一句依据只依据 user behaviors 中的证据评分。
不得因模型没有猜中评论原文而扣分，也不得把“看过/点击过”直接视为会评论。

## 可选变化

可以改变预测窗口、近邻候选来源和证据强弱，但不能改变集合式多选合同、完整 Note 卡字段或最多 30 个候选的限制。

## 种子提示词

题面会提供 <user behaviors>、明确的预测窗口以及题目所需的候选或状态定义。请根据 <user behaviors>，从题面完整 Note 候选卡中预测窗口内会被用户评论的 Note 集合。不得把浏览、播放、点赞或收藏升级为评论；答案允许零个、一个或多个 Note。只使用题面给出的信息，不得新增、删除、改写候选或使用未披露的未来结果。
## 不出题/不合格

证据、候选或 gold 无法闭环，目标无法可靠对齐，或题目要求凭空推断时不出题。
